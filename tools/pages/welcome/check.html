Stack checker

Will it open? Ask the file.

Drop a LiveCode stack, a script-only stack, a HyperCard stack or a .zip of them. The checker reads the file the way OXT-Beyond’s engine starts to, and says what will work, what differs, and what to do next.

  • Read in this page: nothing is uploaded
  • Nothing in the stack runs
  • Free, no account

What it reads

Everything the file says about itself

The checker reads the stack’s bytes the way the engine starts to read them, and stops before anything could run.

Its format

From the header: format 2.4 to 8.1, and so the LiveCode that saved it, or a format newer than OXT-Beyond reads.

Its widgets

Each kind of widget in it, and whether OXT-Beyond has that widget.

The libraries it calls

tsNet, mergJSON, revDB, revBrowser, the Data Grid, mobile and iOS calls, mergExt, and the stacks it starts using.

Where it was meant to run

The platforms ticked in its Standalone Application Settings: Windows, macOS, Linux, Android, iOS or HTML5.

Its scripts

Roughly how many handlers it has, and some of their names, without running one.

Passwords and damage

A password-protected stack, a file cut short, or one a text-mode transfer has damaged.

HyperCard stacks

HyperCard 1 or 2, how many cards and backgrounds, and the mark the Merryxmas virus leaves.

.zip files

Every stack inside, each with a report of its own.

Honest about it

What it can’t tell you

The checker reads; it never runs. Here is where that stops it, and why your file is safe with it.

Out of its reach

  • How the stack behaves when it runs. It reads the file and runs nothing, so a script can still do something different. The Stack Player is the next step.
  • Which LiveCode saved an 8.1 stack. LiveCode 8.1 and 9 both save that format, so the file can’t say. Stacks from LiveCode 10 and 11 haven’t been tested yet.
  • Libraries it doesn’t know. It knows the common ones; any other shows only as a name a script calls.
  • What’s behind a password. It sees that a stack has one, and no further.

Your file stays yours

  • Nothing is uploaded. Your browser hands this page the file’s bytes; there is no server to send them to, and the page asks none for anything once it has loaded.
  • Nothing runs. The checker reads bytes. It never loads the stack into an engine.
  • Gone with the tab. A report from the front page’s stack window waits in this tab’s session storage so this page can show it, and goes when the tab closes.
  • One script you can read. The whole checker is stackcheck.js, plain JavaScript with comments.

It opens? Play it.

The Stack Player runs your stack in a browser tab, with nothing to install. The desktop IDE installs next to the LiveCode you have.
