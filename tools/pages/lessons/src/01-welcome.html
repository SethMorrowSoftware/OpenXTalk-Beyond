What is xTalk?

xTalk is a family of programming languages that read almost like English. It began in 1987 with HyperTalk, the language of Apple's HyperCard, which let teachers, artists and shopkeepers build their own programs. It lives on in LiveCode, OpenXTalk and OXT-Beyond, which is free and runs on Windows, macOS, Linux and in your browser.

Stacks, cards and scripts

An xTalk program is called a stack. A stack is a window, and it holds one or more cards, like a stack of index cards. On each card you place controls: buttons, text fields, pictures, menus and so on. You draw them with the Tools palette, much as you would in a drawing program.

Every object, from a button to the stack itself, can have a script: the xTalk that says what it does. A button's script usually waits for a click:

When you click the button and let go, xTalk sends it the message mouseUp. The script has a handler for that message (everything from on mouseUp to end mouseUp), so its lines run: answer shows a little dialog with the words in quotes. You will meet handlers and messages properly in later lessons; for now, notice how readable it is.

A HyperCard stack from the 1990s used the same words: on mouseUp, answer, put. OXT-Beyond still understands them, and can even open old HyperCard stacks (File > Import Stack > HyperCard Stack).

Your first line

The first command most people learn is put. With nothing after it, put shows a value. Text goes inside double quotes; numbers do not need them.

The program runs from the top, one line at a time. Each line is one instruction, which xTalk calls a statement.

Where to run the examples

You can try every example in these lessons yourself. There are three good places:

  • The xTalk Academy's playground. Choose Help > xTalk Academy. The playground on the right of the window runs whatever you type when you press Run (or Ctrl+Enter), and shows every put on a line of its own in the Output, exactly as the lessons do. This is the best place to start.
  • The Message Box. Choose Tools > Message Box, type a line and press Return. It is handy for a quick sum or to ask about an object, but each put replaces the last one, so you only see the final value.
  • A script. Examples marked Script are handlers. Make a button, open its script (select it and choose Object > Object Script), paste, and press Apply. Then switch to the Browse tool and click.

Nothing you type in the playground can harm your computer or your files, and the Academy keeps your work between visits. Experiment freely: change a number, run it again, see what happens.

How to read the lessons

Each example has a bar on top that says what it is, and a Copy button. Under it, Output shows exactly what the playground shows when you run it: the lessons are checked by running every example on the OXT-Beyond engine, so what you see here is what you get.
