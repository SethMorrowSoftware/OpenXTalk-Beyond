- Sockets: a write to a secure socket now goes while a read on it waits for the rest of a TLS record; the engine (as LiveCode's) held every write back until the next read, so when it read a record with nothing for the script first (a TLS 1.3 session ticket, which Go servers such as Caddy send with their side of the handshake) the request queued behind the handshake never left, and `put url` ended with "socket timeout" (reported by bwmilby, issue #461), and a large HTTPS `post` could end with no reply. Only those writes, which used to wait for good, change; a new Linux CI check, `tools/ci/tls_write_check.py`, holds it (#463)
