- Engine: "the properties" (and "the effective properties") of an EPS, a color palette or a video clip, the templateEPS and the templateVideoClip among them, no longer quits the engine; it gives the properties the object has, without the ones its list names that such an object does not answer (an EPS's postScript, pageCount and the rest, a video clip's playLoudness). LiveCode Community 9.6.3 quit on them too. What a script can see: only these three kinds of object change, from a crash to an array; every other object's properties are as before (reported by bwmilby, issue 518) (#521)
- Tests: core/engine/properties-prop gets the properties of the templateEPS, the templateVideoClip and a created EPS, sets the templateEPS's back from them, and pins the templateAudioClip's four keys (#521)
- IDE: the two Color Chooser stacks (colchooser.livecode and revcolorchooser.rev) have their scripts in stack-scripts/ as every other binary stack has: reading the properties of their color palette ended the engine as an EPS's did, so the engine that writes the files could not read them (#521)
- Web: a fullscreen stack follows the page as it gets narrower or shorter, not only wider: the engine sized its window to the page only when the page moved the canvas, which a centred canvas does as the page widens and cannot do as it narrows, so the stack grew with the browser's window and never shrank back. Each open fullscreen stack now takes the page's new size when the browser's window changes, in every fullscreenMode. What a script can see: only fullscreen stacks on the web change, now covering the page after it narrows (with resizeStack in the modes that resize the stack); stacks that are not fullscreen, and the desktop and mobile engines, are as before (reported by OpenXTalkPaul, issue 515) (#521)
- CI: the web check makes the probe's window fullscreen in the exactFit, showAll and no fullscreenMode, and the page wider, narrower than it began and as it was; the window must cover the page each time (#521)
