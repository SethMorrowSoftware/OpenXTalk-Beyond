- Android: a stack built with an Android library (.aar: an extension's jvm-android folder, a Play Services dependency) gets the library's R class with the ids its resources have in the package. They were numbered from the library's resources alone, so a library that looked up one of its own resources could get another, or none. The builder now makes them in one aapt run over the app's resources and every library's, as the package step reads them (#501)
- CI: the Android check builds the app probe with a real Android library it makes with the JDK (android_check.py ide --aar), and checks that the package carries the library's class, its R class, and its string at the id that R class gives (verify --aar) (#501)
