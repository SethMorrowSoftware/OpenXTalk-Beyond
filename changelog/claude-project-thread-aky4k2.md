- Databases: SQLite's math functions (sqrt(), pi(), exp(), pow() and power(), mod(), ln(), log(), log2(), log10(), ceil() and ceiling(), floor(), trunc(), radians(), degrees(), and the trigonometric and hyperbolic functions) and its REGEXP operator, with regexpi() for a match that ignores case, work in every SQLite connection on every platform, the web and Android included; a query that used one failed with "no such function". They are SQLite 3.54.1's own code: its math functions, and its regexp extension, whose matcher never takes longer than the pattern's size times the text's. The driver adds them to each connection instead of building them into SQLite, so that a stack that loads an extension of its own with these names (the "extensions" option) still gets the extension's, as before: extension-functions.c's log() is the natural logarithm, where SQLite's is base 10 (#613)
- Databases: what a script can still see differently: a query with one of these names runs where it failed; PRAGMA function_list lists them; a stack that loads its own extension only after such a query fails would no longer load it; and an extension that adds one of these names for any number of arguments (none is known) cannot replace it from the query that loads the extension, as SQLite replaces no function with one of the same number of arguments while a query runs. A database whose views, indexes or triggers use them needs them wherever it is opened: LiveCode, and OXT-Beyond before this version, have none of them (#613)
- Dictionary: revOpenDatabase says which SQLite it is and describes the math functions and REGEXP (#613)
- Tests: the math functions and REGEXP through revDB (tests/lcs/core/database/sqlite_functions), their answers held to those of a SQLite built with its own math functions, a loaded extension's functions to taking their place (tools/ci/tests/test_thirdparty_libraries.py), and the web engine's database to having them (the web probe's database-functions check) (#613)
