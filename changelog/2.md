- Background Jobs library (org.openxtalk.library.async): asyncShell, asyncProcessOpen, asyncReadFile, asyncWriteFile, asyncAppendFile, asyncCopyFile and asyncListFolder run a shell command or a program, read, write or copy a file, or list a folder while the window stays live; each returns at once with a job's number and the calling object is sent a message when the job is done. asyncCancel, asyncStatus, asyncProgress and asyncJobs act on the jobs under way. shell(), open process and URLs are unchanged (#2)
- Tests: the test library's requirement "extension" skips a test where an extension it loads is not there, as in an Android standalone built by a release's IDE that has no such library yet (#2)
- Tests: a freeze meter (tests/lcs/extensions/libraries/async-freeze.livecodescript) writes to each run's output how long a stack's own messages stop during a shell command, a large file's reading, writing and copying, and the listing of a tree, with the blocking call and with a background job (#2)
- Extensions with native code: MCAsyncNativeCall has a C function of the extension's library called on another thread and sends a message when it has returned, and a wake (MCAsyncNativeWakeCreate, MCAsyncNativeWakeFunction, MCAsyncNativeWakeContext, MCAsyncNativeWakeDelete) lets a thread of the library's own tell the script that it has something, which arrives as one message however many times it was signalled; an extension binds to them with "<builtin>" ("Native code that takes time, or has threads of its own" in the Extending guide) (#2)
- Background Workers library (com.livecode.library.worker): workerStart starts a worker, the engine again with no window, that runs the handlers of a script while the stack goes on; workerCall calls one of them with any parameters (text, numbers, binary data, arrays) and returns at once, and the calling object is sent a message with the result or the error. workerSendProgress reports progress from a worker, workerStop stops one and the call it is running, workers and workerPending list them. In a standalone the worker is the application itself, which the library takes over before the application's own startup handler runs, so the library and the Background Jobs library must both be among its inclusions (#2)
- Background Database library (com.livecode.library.asyncdatabase): asyncDatabaseOpen opens a database connection that a worker holds, and asyncDatabaseQuery and asyncDatabaseExecute run a query or a statement there and return at once; the object that asked is sent a message with the rows (keyed by the columns' names) or the result, or revDB's error. A connection's requests run in the order they were made, and connections at the same time; asyncDatabaseClose ends one, with the request it is running. revDB's own calls are unchanged. On the desktop, with every database revDB has a driver for (#2)
