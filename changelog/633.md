- Processes: the new global property `the closeEndedProcesses`, false by default. When it is true, a process opened for read or update leaves `the openProcesses` and `the openProcessIDs` once it has ended and a `read from process` has taken its output to the end ("eof"); `close process` of it afterwards does nothing and says "process is not open". By default such a process stays listed, with the ID 0, until `close process`, as it has since LiveCode 7 (the engine's end-of-output check compares a pipe's position with its size, which a pipe has neither of; LiveCode 6 asked the stream itself). A process opened for write or neither leaves when it ends, as before. On Windows a process read to its end has always left by itself (the engine reads a pipe's position and size as equal there), so the property makes Linux and macOS behave as Windows does and changes nothing on Windows. Its name is no keyword, read only after "the" where a line did not compile without it, as `the sequencesAsLists` is: a variable or handler of that name, and `the closeEndedProcesses of` an object (a custom property), are as they were (#633)
- Dictionary: openProcesses, openProcessIDs and close process say that, on Linux and macOS, an ended process opened for read or update stays listed with the ID 0 until it is closed, and closeEndedProcesses is new (#633)
- Tests: tests/lcs/core/files/process-list.livecodescript pins the default (on Linux and macOS an ended process read to its end stays listed, ID 0, until close process; on Windows it leaves), the new property's effect, unread output kept, a running process kept, a process opened for write leaving when it ends, and the name as a variable, a handler and a custom property as before; tests/lcs/parser/close-ended-processes.parsertest the same at parse time (#633)
