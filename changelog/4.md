- Background Workers library: in a web standalone, workerStart starts a worker that is a web worker of the page, which loads the engine again with the standalone's files and runs the script's handlers while the page goes on; workerCall, workerSendProgress, workerStop, workers and workerPending work there as on the desktop. Before, a worker started in a browser ended at once with "not supported", as it still does on Android and in the web IDE. A worker in a browser has a file system of its own, and each is a whole engine, with as much of the browser's memory as the page's (#4)
- Web engine: an engine loaded in a web worker starts without a user interface, as "-ui" starts the desktop's: its stacks open without a window, and its waits give the worker's events a turn. Module.livecodeEngineURL is the address of the engine's script, recorded as it loads unless the page has set it. A page's engine is unchanged (#4)
- Background Database library: in a browser asyncDatabaseOpen still ends with "worker failed: not supported", now without starting a worker (#4)
- CI: tools/ci/web_workers_check.py runs workers in a web standalone in Chromium, Firefox and WebKit (web.yml): calls with text, numbers, binary data and arrays both ways, errors, progress, output, waits and messages in a worker, two workers at once while the page's timer goes on, stopping, a worker whose script quits, a script that does not compile, and the database library's refusal (#4)
