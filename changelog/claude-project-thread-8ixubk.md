- HyperCard import: text a script runs with "do" now gets the same rewrites as the stack's scripts, as HyperCard ran it with a script's rules. Rule T81 puts each do's text through the library's new hcDoText, which gives it back unchanged when it compiles and otherwise rewrites it (revHyperCardDoText), with the variables the import renamed in that handler named the same way, so "do "set the icon of bg btn sound to sound" & x", "do "put there is a" && fspec && "into exists"" with fspec "cd fld Title", and "do "global" && tNames" naming fileName or sound now run where they stopped with "do: error in source expression" (13 stacks of the 2,202 in the re-sweep of 2026-11-16). What a script can see: only scripts of newly imported HyperCard stacks change; text that compiled runs as before, except text naming a variable the import renamed in that handler, which now reaches that variable as it did in HyperCard; text the rules cannot fix stops as before; a do in another language ("do x as "AppleScript"") is unchanged
