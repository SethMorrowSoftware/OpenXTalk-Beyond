- Android Documents library (org.openxtalk.library.androiddocuments), new: androidPickDocument shows Android's own "Open document" screen, androidDocumentName says a document's name, and androidCopyDocument copies a document that Android gave the app by a content address into a file; it needs no permission, and off Android each handler throws (#569)
- Android builder: a stack's new `android,documentTypes` setting (MIME types) offers its app where the user opens a document of one of those kinds, in a file manager, a mail app or a browser; the address arrives in urlWakeUp and mobileGetLaunchUrl(). A stack without the setting builds as before (#569)
- Android Stack Player, a first proof (tools/android-player): an Android app that takes a stack file from the "Open document" screen or from another app, copies it into its own library and plays it, and comes home on Android's Back; built by the IDE's own Android builder with OXT-Beyond's engine, with the Internet permission and no other. Not in a release yet (#569)
- Tests: tests/lcs/androidplayer/stack-player.livecodescript, tests/lcs/extensions/libraries/androiddocuments.livecodescript, the builder's unitDocumentTypes, and the "Android Stack Player" workflow, which builds the player and plays a stack in it on an Android 13 emulator by each way a stack comes in (#569)
