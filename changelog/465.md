- Windows: a switch between the light and the dark appearance while the IDE or a standalone runs is followed at once: standard buttons and option menus, the title bars and every window. Before, the engine never acted on Windows' notice of the switch (it read the notice's name as a wide string in a window that is handed an ANSI one), so after a switch to dark a button stayed light grey under the dark appearance's white words until the next start (a white button with white text, reported by richmond62), title bars kept the old appearance, and systemAppearanceChanged was never sent on Windows. The message is now sent there, once for each change; the engine also finds a change by itself when it reads the setting as it draws, should no notice come (#465)
- Windows check: a job with visual styles on Windows Server 2022 and 2025 switches Windows between light and dark, with and without its notice, and measures a button, an option menu and a combo box in the standalone engine, with the title bar, the systemAppearance and the message; the same check can be run on a published release, and run on 0.2.7 it measured the fault (#465)
