- SVG: drawingSvgCompile and drawingSvgCompileFile take a list of options, "styles", "opacity", "ids", "clip" or "all": an SVG's style sheet colours (type, class and id selectors), its opacity, references to ids such as "grad-1", and its clip paths, which drew black, opaque or unclipped before (a drawing with a clip needs this engine or later). With no options a drawing compiles to the same bytes as before; the IDE's SVG import uses "all" (#307)
- SVG: an SVG whose path writes an arc's flags together, as minifiers do ("a1 1 0 112 0"), compiles; it failed, and up to now every SVG compiled after it in the same session failed too (#307)
- Engine: a drawing (an image made from an SVG) with a polygon or polyline of 32 points or more draws it, and the shapes after it; the engine misread the count and drew nothing from there on. The drawing library now also writes such shapes as paths (#307)
- Engine: an arc whose ends are a diameter apart (a half circle, as in the Korean flag) draws in full; rounding could make it a sliver (#307)
- Drawing library: drawingDecode reads a drawing back as its shapes, with their paths, colours, gradients and line styles; drawingFlatten turns it into polygon points; drawingSvgDecompile writes it back out as SVG (OpenXTalkPaul, openxtalk.org p=25842) (#307)
- Image context menu: Convert to Graphics, on an image made from an SVG, makes a group of polygon graphics with the shapes' colours, gradients, line styles and opacity, which can be edited like any graphic; shapes under a clip path go in a group the size of the clip (richmond62, openxtalk.org p=25843) (#307)
- Engine: drawings can clip, with three new drawing opcodes (ClipBegin, ClipEnd, ClipRestore) that the drawing library writes for an SVG's clip paths when asked; drawings without them draw as before (#307)
- Engine: in a drawing's path, a smooth quadratic curve (SVG's T) after another one bends as it should; from the second on it drew as a straight line (#307)
