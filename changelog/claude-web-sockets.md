- HTML5 standalones and the Stack Player: `open socket to` a ws:// or wss:// URL opens a WebSocket, and the socket works as a desktop one does: `with message`, `read from socket` (for a count, until a string, or all there is) and `write to socket` with and without a message, `socketClosed`, `socketError` and `socketTimeout`. What a script writes goes as one message (text when it is UTF-8, binary otherwise); what the server sends is read as one stream of bytes. Any other socket name fails with "not supported", as before (#TBD)
- Tests: the web engine's sockets against a WebSocket echo that the web tests' server now has (tests/lcs/core/network/websocket), and em-socket.js run in Node against the same echo (tools/ci/tests/test_web_sockets.py) (#TBD)
