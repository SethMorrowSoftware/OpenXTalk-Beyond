- OXT-Beyond Server: the session files and their index (`lcsessions.idx`) can be read and written by the user the engine runs as and by no other on Linux and macOS; they were readable by every user of the machine, with `$_SESSION` and every visitor's address in them (#PR)
- OXT-Beyond Server: a session ID with a folder separator in it (the browser's cookie says what the ID is) is not used, and the session gets a new ID. On Windows such an ID made `start session` write a file outside the session folder, which the clean-up of expired sessions later deleted; on Linux and macOS `start session` failed with an error. An index entry an older engine wrote for such an ID is dropped without touching its file (#PR)
- OXT-Beyond Server: two new properties for the session cookie, off by default so that the cookie is LiveCode's until a script sets them: `the sessionCookieSecure` (the Secure attribute) and `the sessionCookieSameSite` (`lax`, `strict` or `none`; empty sends no SameSite attribute). The two names are new words of the language: a script that used one of them as a variable's name without declaring it must rename it (#PR)
- Server check: the session cookie's attributes by default and as set, a session ID that names a file outside the session folder, and the modes of the session files, as a CGI program on every platform and through Apache on Linux; an engine test suite for the two properties (#PR)
