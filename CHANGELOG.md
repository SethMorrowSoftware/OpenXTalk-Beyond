# Changelog

Every change made to this repository since Tom Perry's last commit,
`d98d01da` *macOS arm64 and modern-toolchain portability fixes* (16 June
2026), which came in with pull request #7. Each line is one commit, under
the first release that included it, newest release first and in the
order the commits were merged within it; the number in brackets is the
pull request that brought it in. Commits that were later reverted are
listed too, and so are their reverts.

OXT-Beyond 0.0.1 and what came before it (the build of LiveCode
Community for Windows, and OpenXTalk Lite's history up to 1.15) are
described in [HISTORY.md](HISTORY.md). What each release adds, in
words, is in the [README](README.md#the-ide) and on the
[Releases page](https://github.com/SethMorrowSoftware/OpenXTalk-Beyond/releases).

## 0.2.7-rc.6.12 (2026-11-01, pre-release)

- Engine: the version reads 9.7.1-BeyondEngine, where it read 9.7.1-OXT, in `the version`, the About box and `-v`; the long version ends "(BeyondEngine)", and the web engine's files, the Linux window class, the server's home folder and the Community licence file take the new name. 9.7.1 and build 25923 are unchanged, so a script that takes the part before the "-" (`set the itemDelimiter to "-"`) or reads `the buildNumber` gets what it did; one that looks for "OXT" in the version no longer finds it (tperry2x, openxtalk.org p=25816) (#293)
- Object menu: Copy Graphics as SVG Paths also puts the SVG on the clipboard in Illustrator's formats (com.adobe.illustrator.svg, com.adobe.illustrator.svgm and com.adobe.svg), so it pastes as vector paths into Illustrator or VectorCraft; the plain text is as before (OpenXTalkPaul, openxtalk.org p=25820). The IDE tour reads each one back (#293)
- Inspector: a scrollbar's Orientation can be set, Horizontal or Vertical, which swaps its width and height about its centre; it was read only, and a scrollbar could only be turned round by dragging it (TerryL, openxtalk.org p=25821). The IDE tour sets it as the Inspector does and reads it back (#293)
- Web: on a page that follows a browser set to dark, a check box with no colour of its own draws a dark box with a white tick. Its box was white there, so an unticked one looked ticked; light pages are as before. The web check reads both in a dark browser (#293)
- macOS 11 and later: a standard button taller than 30 points is drawn its whole height, with the Mac's rounded bezel; the bezel stayed 21 points high in its middle (Skids, openxtalk.org p=25824). Buttons of the usual heights are as before, and the IDE tour checks a tall one on every platform (#293)
- CI: the standalone check lets a runtime that a package takes from the runtimes asset report the version the asset's PROVENANCE file records for it (the 32-bit Windows runtime of oxt-runtimes-0.2.7-rc.6.11, built before the rename, still read 9.7.1-OXT and failed the Windows build); any other version still fails, and the package's own runtime must read the engine's. "Tag a release" counts a change to the `version` file as engine source, so it refuses to tag until the runtimes asset is rebuilt after one (#293)
- GitHub Pages: a new front page, a night sky over an orange horizon with a stack that answers its button, a card for each part of the site, a Downloads section linking the latest release's files, and a check of its links in a browser (#295)
- HyperCard corpus sweep: "answer" and "ask" get their default button as a person would give it, where a run without the IDE gave scripts the dialog's request back as the reply; hidden and disabled buttons, which a person cannot click, are no longer clicked; the log has `DIALOG` and `SKIP` lines for them, and runs from before are not comparable with runs after (#296)
- Web: a Web Games section on the GitHub Pages site, with Pixel Maker: a platformer and level maker in xTalk Script with Box2Dxt physics, running on the Stack Player's engine (#301)
- IDE: OXT-Beyond Home, one window for the welcome, the xTalk Academy and Learn, with one sidebar of five places (Home, Academy, How-to, Guides, Examples). - HyperCard stacks that stopped as they opened on an external now open: the HyperCard Library stands in for Files, ResText, SystemPath and FindFolder, written from their own documentation (the Star Trek guides, SonnetFolio and its 154 sonnets, BGC's stacks), and `field "Season" of card it-1` is the card before the last, as in HyperCard (#300)

## 0.2.7-rc.6.11 (2026-10-31, pre-release)

- Standalone Settings: on Linux and Windows, looking at the OS X card no longer turns off every Mac target of the stack; the targets are shown as they are and kept, and are changed only on a Mac (#290)
- Databases: revRollBackDatabase and revdb_rollback roll a PostgreSQL, SQLite or ODBC transaction back, as their dictionary entries say; they committed it (#290)
- Databases: the MySQL driver's encrypted connections work again, over TLS 1.2 or 1.3; it asked for TLS 1.0 alone, which OpenSSL 3 and current MySQL and MariaDB servers refuse (#290)
- Linux: a new global property, the useDesktopAppearance (false by default), lets the systemAppearance follow the desktop's light or dark setting (GNOME's color-scheme, or a GTK theme named "dark"), with systemAppearanceChanged when it switches; Preferences > Appearance has "Follow the desktop's light or dark setting" for the IDE. The engine still draws in the GTK theme's colours (#290)
- Script Editor: a dark colour scheme saved by an early Beyond build (0.2.1 to 0.2.3) no longer overrules the scheme picked in Preferences, which left every word black on the dark background and Vibrant ignored; a scheme name the editor does not know loads the readable scheme for its background, and picking a scheme, or Custom, drops the old dark one (tperry2x) (#290)
- Engine: a script that deletes the group of the control its message was sent to (or the stack of the card it was sent to) while that message is still being handled no longer frees the control under the message, which the engine went on to use; it lives until the message is done. Turning a breakpoint or watch off in the Script Editor's Breakpoints pane crashed the IDE this way (mwieder, tperry2x; an old LiveCode bug). Linux CI now runs these tests under valgrind as well (#290)
- Fields: Undo takes out a typed Return, as it takes out typed text, and a Return typed with text is undone with it; it made no undo record, so Undo left it there, or undid text typed before it, at a place the Return had moved (#291)
- Web IDE: the zip leaves out the files of Source Code Pro, which the web engine cannot load (it showed code in Droid Sans Mono already), and an unused archive of the Linux theme, 1.3 MB of the zip (2.2 MB unpacked) (bwmilby, OpenXTalkPaul) (#291)
- Script Editor: the Handlers button above the script keeps the script's selection: the list of handlers takes the focus, which cleared it, and when the list closes with no handler picked (a click elsewhere, or Escape) the selection comes back, unless the click went into a field (tperry2x, openxtalk.org p=25787) (#291)
- Script-only stacks: saving one first copies the file as it was to `<file>~`, as saving a binary stack does, puts it back if the new text cannot all be written (a full disk), and deletes the copy once the save has worked; a `~` file that is there already is left alone. A write that the system held back and then could not make is now reported (`the result` is "error writing stack script file") instead of leaving the file cut short with an empty result (seth's choice 6A) (#291)
- Web: when the browser stops keeping the home folder, where stacks are saved (a full disk, the storage refused, as in a private window), the web IDE shows a "Not saved" bar with the browser's reason, until a write works again; before, only the browser's console said so, and a stack that looked saved was lost when the tab closed. A page of its own can listen for the `oxtstoragestate` event or read `Module.livecodeStorageError` (seth's choice 6A) (#291)
- Web: a new Fields setting in the Standalone Settings' HTML5 pane, "White" (as before) or "The card's grey", draws fields, list fields and combo boxes that set no colour in the light appearance in the grey of a card that sets none, as the dark appearance already does; the page carries `<meta name="oxt-field-background" content="card">`. Pages without it keep white fields (bwmilby, openxtalk.org p=25615; seth's choice 9A) (#291)
- Help > Dictionary Online opens OXT-Beyond's own Dictionary of xTalk Script and xTalk Builder, titled "OXT-Beyond Dictionary", on the project's web pages (https://sethmorrowsoftware.github.io/OpenXTalk-Beyond/dictionary/), made from each release's web IDE, instead of the classic dictionary at openxtalk.net, which calls itself the LiveCode Dictionary (richmond62; seth's choice 12A) (#291)
- macOS: a stack or card with no colours of its own follows the Mac's own colours, light or dark, and changes as soon as the Mac switches between them. In the dark appearance it is drawn in the Mac's window colour instead of a fixed 61,61,61, and the effective backgroundColor and foregroundColor of a stack or card (and of any control without colours of its own) read the colours of the appearance in use, where before they kept those of the appearance the IDE or standalone started in. The light appearance looks and reads as before; a stack or card printed in the dark appearance takes the light one's colours. The classic toolbar leaves its colour to the engine so that it matches the other palettes (bwmilby, openxtalk.org p=25665, p=25668; seth's choice 1A) (#291)
- Widgets: a header bar, navigation bar, segmented control, switch button or tree view whose colours nobody set by hand follows light and dark. The IDE gives a new one its light defaults (244,244,244 behind its labels, with dark labels and a grey border) as colours of its own, so it stayed light on a dark card; in the dark appearance, on a dark card, a colour that is still its light default is now drawn in a dark one (64,64,64 behind light labels). A colour set to anything else is drawn as set, the properties read what they did, and the light appearance, and Linux unless the useDesktopAppearance is true, look as before. A colour set by hand to exactly the light default is drawn in the dark one too. Widgets get the engine handler MCWidgetGetMyPaintForAppearance for this (bwmilby, openxtalk.org p=25665, p=25680; seth's choice 2A) (#291)
- Object menu: Copy Graphics as SVG Paths puts the selected graphics on the clipboard as an SVG document, a path for each graphic from its effective points, in its fill, line colour and width. The item is from OpenXTalkPaul's DPE IDE and came by way of OpenXTalk Lite 1.01, which added it and its call to `revOXTIDEGraphicPointsToSVGPath` but never the command, so the item did nothing (OpenXTalkPaul, openxtalk.org p=25819, p=25820). The IDE tour picks the item with graphics selected and reads the clipboard (#292)
- Standalone runtimes for the other platforms (Windows x86 and x86-64, Linux x86 and x86-64) rebuilt from 0.2.7-rc.6.11's engine: the asset `oxt-runtimes-0.2.7-rc.6.11` replaces `oxt-runtimes-0.2.7-rc.6.10` (#292)
